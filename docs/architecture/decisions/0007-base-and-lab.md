# ADR 0007 — Separar Genesis Base e Genesis Lab
Status: aceito
Data: 24/11/2026
Contexto e restrições: o Aceiro (P10) herdou 287 arquivos da fundação e importou cinco deles (`core/hydration`, `core/app-config`, `motion/presets`, `styles/base.css`, Motion/Phosphor). Nenhum componente visual do design system entrou na tela. O CSS base saiu com 56 KB, pois o Tailwind varre o design system inteiro. O produto carregou o histórico das fases, quatro mundos e as sete fontes deles, além do módulo de IA, da camada de evidência, das receitas e do próprio gerador, sem usar nenhum. O que produziu a qualidade foi o processo: protocolo, conceito, DESIGN.md e `design:verify`.
Alternativas consideradas: (1) manter um repositório e ampliar a lista de remoção do `genesis:new`. Custo baixo, mas a fundação continua misturada com laboratório, vitrine e histórico, e cada produto herda o histórico Git. (2) Repositório novo e enxuto como base, mantendo este como laboratório. Escolhida. (3) Pacote npm da fundação. Prematuro: o valor está em arquivos que o produto edita (DESIGN.md, rotas, CSS), não em uma API versionada.
Decisão e justificativa: criar `genesis-base` (repositório local novo, histórico próprio) com somente o que todo produto usa: scaffold TanStack Start + Vercel, motor de design + `design:verify`, `core`, primitivas de comportamento, motion essencial, `CompareMask`, testes e documentação do protocolo. IA e dataviz são módulos opcionais (`--with ai,dataviz`). O gerador cria o produto por cópia dos arquivos versionados, com `git init` novo e sem o próprio gerador. Este repositório passa a ser **Genesis Lab**: Studio, mundos, demos, ensaios, histórico das fases e avaliações. Melhorias de fundação nascem na Base; o Lab pode recebê-las quando precisar demonstrar algo.
Evidência: `docs/experiments/ACEIRO-P10.md`; inventário de imports do Aceiro (`grep` em `src/features/aceiro` e `src/routes`); CSS de produção `base-*.css` = 56.703 bytes no build Vercel do Aceiro.
Consequências e riscos: duas cópias do motor de design podem divergir; mitigação: a Base é canônica e o Lab registra a origem. Produtos antigos (ISOTERMA, Entrelaços, Aceiro) continuam válidos e não migram. Mundos deixam de estar na Base; o DESIGN.md comentado do Aceiro entra como exemplo de referência.
Rollback: a Base é aditiva. Removê-la e voltar a usar `genesis:new` deste repositório.
Responsável e aprovação: aprovado pelo responsável em 24/11/2026 ("pode criar um repo novo pra separar a base do lab").
